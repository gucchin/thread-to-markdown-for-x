## 作業メモ

- `thread.ts` を「DOM の読み取り」（`readTimeline`：ポストとセクション見出しの列）と「範囲の判定」（`selectThread`／`buildThread`）に分けた。自動スクロールは各ステップの読み取りを `MergedTimeline` で ID 順に統合し、同じ判定をかける（手動のときと結果の規則が同じになる）
- 統合：新しいエントリは、同じ読み取りの中で直前にある既知のポストの直後に入れる。読み取りの先頭が未知なら最初の既知のポストの直前、既知が無ければ末尾（下にしかスクロールしないため）。見出しは ID が無いが、会話ページの見出しは「もっと見つける」の 1 つだけ（フィクスチャで確認）で、そこで止まるので、同じものとして扱う。省略表示のポストは、後で展開された版で置き換える
- 停止条件と理由：スレッドの終わりが見えた（`end`）／新規 0 件が 3 回連続（`idle`）／上限 100 件（`limit`）／上限 30 秒（`timeout`）／中止（`aborted`）。`end`・`idle` は自然な終わり。それ以外は「続きがあるかもしれない」ので、Markdown 末尾の警告と、トーストの警告表示（例：`⚠️ 100 posts copied (post limit reached)`）を出す。上限件数で止まった場合は 100 件に切る
- 中止はスクロールを止めて、それまでの分をコピーする（何も出ないより実用的と判断。PLAN §7.6 に追記）。中止はステップ間の待機中でもすぐ効く
- 待機：`waitForSettle`（MutationObserver。400ms 変化が無ければ収束、最大 2.5 秒）。observer とタイマーは必ず片付ける。スクロール位置は `finally` で戻す（例外時も）
- 省略表示（「さらに表示」）のポストは、描画されている間に展開する。展開できなかったポストを何度も待たないよう、試すのは 1 回だけ
- UI：進捗トースト（`Collecting posts… N`、「Stop」ボタン。自動では消えず、結果トーストに置き換わる）。スレッドが画面内で完結しているときはスクロールもトーストも出ない。ポップアップとオプションページに自動スクロールのチェックボックス（設定 `autoScroll`）。フォームの処理は `shared/settingsForm.ts` に共通化
- テスト：仮想スクロールを模した偽ページ（表示範囲だけを返す）で、各停止条件・位置の復元・展開・統合の順序を検証。主要な行はミューテーションで落ちることを確認。jsdom 上でビルド済みの content.js も動かし、設定の読み込み・全件モード・進捗トースト→結果トーストを確認した
- 制約：メインより上は、開いた時点で描画されている分だけ（上にはスクロールしない）。X が「返信をさらに表示」のようなボタンで続きを隠している場合は押さない（表示文言での判定になるため）。そこで新規 0 件が続いて止まる

### 実機確認（ユーザー作業）

1. `npm run build` → 拡張を再読み込み → x.com のタブも再読み込み
2. ポップアップの「Auto-scroll…」をオンにする
3. 画面に収まらない長いスレッド（同じ著者が 10 件以上など）の 1 件目を開き、ページ内ボタンでコピー。右下に「Collecting posts… N」と Stop ボタンが出て、ページが自動で下にスクロールし、終わると元の位置に戻る。貼り付けると全件入っている
4. もう一度実行し、途中で Stop を押す → すぐ止まって元の位置に戻り、それまでの分がコピーされる（トーストが ⚠️ … (stopped)）
5. 全件モード＋自動スクロールで、リプライの多いポストを開いてコピー → 100 件か 30 秒で止まり、⚠️ (post limit reached) か (time limit reached)
6. 3〜5 を何度か繰り返した後、Chrome のタスクマネージャ（Shift+Esc）で x.com タブのメモリ・CPU が増え続けていないこと
7. 自動スクロールをオフに戻すと、従来どおり画面内だけでコピーされる
