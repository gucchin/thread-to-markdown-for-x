## 作業メモ

- **既存の不具合を修正（著者モードにも影響）**：会話の下の「もっと見つける」（おすすめ）に**同じ著者のポスト**が出ると、スレッドの続きとして収集していた。image3・special の 3 件目がこれで、スナップショットにもそのまま入っていた（image3 の 3 件目はメインより前の時刻の投稿）。セル内の `h2`（見出し）で区切り、メインと同じセクションだけを対象にするよう `thread.ts` を変更。`SELECTORS.sectionHeading` を追加。raw の全フィクスチャで、セル内の `h2` はこの見出しだけ、ポスト内に `h2` は無いことを確認した。リプライ全件モードでは、これが無いとおすすめが丸ごと入っていた
- リプライ全件モード：メイン以降はセクションの終わりまで全部。上方向はモードによらず同一著者のみ（PLAN §7.5 の「メイン以降」に合わせた）
- 見出しの著者は全件モードの**全見出し**に付ける（メインの著者のポストも）。誰の発言かを LLM が取り違えないように。`### Tweet 1 — @user1 (Main)`
- メタ情報の通常行：見出しの次の行に `2026-10-14 09:12 +09:00 · https://...` をそのまま書く
- frontmatter：§8.2 の項目を出力の先頭に。文字列は `JSON.stringify` で引用（YAML の二重引用符文字列として有効）。メインの日時が無ければ `date` を省く
- 設定は `extractAndCopy({ settings })` に渡す（欠けた項目は既定値）。`toMarkdown` は `frontmatter`・`metaFormat`・`authorInHeadings` を受け取る
- ポップアップ：モード切替（ラジオ 2 つ）と Options リンク（`chrome.runtime.openOptionsPage()`）を追加。モードは設定として `chrome.storage.sync` に保存するので、ページ内ボタンとショートカットにも効き、オプションページと同じ値になる。変更直後にコピーしても新しいモードで動くよう、保存の完了を待ってから送信する（テストあり）
- テスト：thread（全件モード・セクション）、markdown（各オプション）、extractAndCopy（設定の受け渡し）、popup（モード切替・保存待ち・Options リンク）、全オプションを有効にしたフィクスチャ 3 件のスナップショット。主要な分岐はミューテーションで落ちることを確認

### 実機確認（ユーザー作業）

1. `npm run build` → 拡張を再読み込み → x.com のタブも再読み込み
2. 他の人のリプライが付いているポストを開き、ポップアップで「All replies」を選んで Copy。貼り付けると、他の人のリプライも入り、全見出しに `— @handle` が付いている。「もっと見つける」より下のポストは入っていない
3. ポップアップで「Author’s thread」に戻してページ内ボタンでコピー → 著者のポストだけになる（ポップアップの選択がボタンにも効く）
4. オプションで frontmatter オン・メタ情報 Normal line → コピーすると先頭が `---` の frontmatter で、各見出しの次の行が `<!-- -->` ではなく通常行
5. ポップアップの「Options」でオプションページが開く
6. （任意）image3 や special のように「もっと見つける」に同じ著者のポストが出るページで、著者モードのコピーにそれが入らない
