## 作業メモ

- 構成
  - `syncButton(env)`：ページを URL に合わせる（ポストページならメインポストのアクションバーの直後にボタンを 1 つ、それ以外ではボタン無し）。何度呼んでも同じ結果になる。位置のずれたボタンや重複は消す
  - `findMainActionBar(doc, mainId)`：URL の ID のポストのアクションバー。ポストの特定には 009 で切り出した `findPermalink` を使う
  - `startPageButton(env)`：監視を始め、止める関数を返す
- 決めたこと
  - ボタンはアクションバーの**中ではなく直後**（次の兄弟要素）に置く。中に入れると、X のアイコンの並び（両端揃え）が崩れるため。アクションバーの下に 1 行増える形になる
  - クリックは `preventDefault`・`stopPropagation` する。X ではポスト全体がリンクで、クリックがポストを開いてしまうため
  - コピー中はボタンを無効にし、連打を無視する
  - デバウンスは 150ms
  - 監視は `main` の配下と、`main` の親の直下（`main` 自体が差し替えられたときに付け直すため）。`main` がまだ無いうちは、出てくるまで文書全体を見る
  - ボタンの色は X の青（`#1d9bf0`）の枠線と文字。ライト／ダークどちらのテーマでも読める
- テスト：`tests/button.test.ts`（17 件）。実フィクスチャでの位置、冪等性、引用付きメイン、URL 変化でのボタンの移動、ホーム・プロフィール・未表示ポストでの削除、重複の掃除、クリックがポストに届かないこと、実行中の無効化、デバウンス、`main` の出現待ち、`main` の差し替え、自分の挿入で無限ループしないこと
- 一時的に壊して検出を確認したこと：`stopPropagation` の削除、`main` の親の監視の削除。後者は最初テストが偶然通ってしまったので（ボタン自身の挿入による変化で再評価が起きていた）、テストを直した
- **実機で確認すること（015）**
  - ボタンが X の表示を崩さないか（ライト／ダーク）
  - X の再描画（React）でボタンが消えたり、X 側にエラーが出たりしないか
  - 遷移（ポスト → 別ポスト → ホーム → ポスト）でボタンが重複・残留しないか
