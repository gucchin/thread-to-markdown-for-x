## 作業メモ

- API：`toMarkdown(result, { timeZone? })`。`timeZone` は IANA 名（省略時はブラウザのローカル）。frontmatter・メタ情報の表示形式・リプライ全件モードの見出しなどのオプションは 017 で追加する
- **仕様変更（PLAN.md §8.3 を更新済み）**
  - 行頭の `#` は、見出しになる形（`#`〜`######` の後に空白か行末）だけエスケープする。`#tag` は見出しにならず、X のポストでは行頭のハッシュタグが多く、Obsidian ではタグとして扱われるため。フィクスチャの `quote.html` で `\#tag1` と出力されて気づいた
  - コードフェンスの内側はエスケープしない（コード中の `#` コメントなどに `\` が付くのを防ぐ）
- **§8.1 の例に無い部分の決め方**
  - 引用内のメディアは、引用ブロックの中に `- [image] url` で並べる。前後に空の `>` 行を入れる（`Source:` がリスト項目の続きとして描画されるのを防ぐ）
  - 引用の日時・URL が無い場合は、その部分（日付の括弧、`Source:` 行）を省く
  - poster の無い動画（ポスト URL を記録したもの）には `(poster)` を付けない
  - メインポストに日時が無い場合、タイトルの日付は抽出日時にする。日時が無い・解析できないポストのメタ情報は URL だけにする
  - 警告が複数ある場合は、1 件ずつ別のブロッククオートにする
- 警告の出どころ：`markdown.ts` が自分で作るのは「閉じていないコードフェンス」だけ。省略表示（Show more）の警告は `result.warnings` として 009 の `thread.ts` が作る。引用ブロック内のフェンスはブロックの終わりで閉じるので警告しない
- §8.1 の例そのものを `toBe` で比較するテストを置いた。フォーマットを変えるときはこのテストと PLAN.md を一緒に直す
- エスケープを一時的に無効にすると 15 件のテストが失敗することを確認済み
- テスト：`tests/markdown.test.ts`（44 件）、`tests/markdown.fixtures.test.ts`（フィクスチャ 5 種 × 4 件。この段階では `thread.ts` が無いので、対象ポストはテスト側で選んでいる）
